# Проверка OCR и независимой разметки

CER — число замен, удалений и вставок символов, делённое на число символов
в эталоне. WER — то же для слов. Меньше — лучше. При большом количестве
лишнего текста результат может быть больше 1; это не ошибка и не обрезается.
Общая метрика взвешена по длине эталонов, а не усреднена по страницам.

## Что готово

`scripts/evaluate_ocr_text.py` сравнивает заранее выбранные текстовые фрагменты.
Он не запускает OCR и не извлекает PDF. Эталон должен быть независимо
проверен по изображению страницы, а prediction — получен из реального OCR.
Пропущенный prediction учитывается как полностью удалённый текст.
Неизвестные/повторные ID и пустые эталоны отклоняются.

Нормализация: Unicode NFC и сведение пробелов/переносов к одному пробелу.
Регистр, цифры, пунктуация и различие латинских/кириллических букв сохраняются.
Ограничение одного фрагмента — 4000 символов: вычисляется точное расстояние
редактирования, а не приближённое сравнение. Большую страницу делить на
заранее фиксированные области, не выбирать только удачно распознанные строки.
Для таблиц заранее фиксировать порядок строк/столбцов. CER/WER не измеряют
правильность связи суммы с нужной строкой — для этого нужны отдельные QA-вопросы.

Вход — локальный JSON с `references` и `predictions`, элементы имеют `id` и `text`.
ID лучше формировать как `doc-01-page-03-region-02`, без персональных данных.
Тексты хранить в игнорируемом `evals/real/reports/`, не коммитить.
Отчёт содержит ошибки, знаменатели и хеши, но не сами тексты. Перед публикацией
проверять даже ID и метаданные; хеш не является гарантией анонимности.

Проверка утилиты на **искусственном примере, не реальная оценка OCR**:

```powershell
uv run python scripts/evaluate_ocr_text.py evals/real/ocr.example.json --output evals/real/reports/ocr-example.json
```

Повторный запуск требует нового имени отчёта: существующие результаты не затираются.
Этот пример намеренно содержит ошибку цифры и пропущенный фрагмент.

## Что ещё необходимо до финального quality gate

1. Новый набор публичных документов: проверить все страницы на персональные данные
   и условия использования; не наследовать privacy-статус старых файлов.
2. Разделить по исходным документам, не по страницам. Поворот/шум того же PDF
   остаются в одном split с оригиналом.
3. До запуска модели зафиксировать вопросы, ответы, точные страницы/области,
   цитаты и вопросы без ответа; последнее подтверждать просмотром всего документа.
4. Отдельный человек проверяет черновую разметку. Машинное предложение эталона
   не называть ручной независимой разметкой. Зафиксировать статус review и дату.
5. Заморозить хеши, модель, код, настройки и пороги. Прогнать baseline и candidate
   через настоящий API, включая отказы, цитаты, задержки и OCR CER/WER.

Старый `holdout.json` остаётся регрессионным. В текущем изменении новых независимых
документов и подтверждённой ручной разметки нет; реальные OCR-метрики не заявляются.
