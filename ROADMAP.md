# TenderLens — план завершения v1.0

Обновлено: **9 сентября 2026**. Это основной roadmap. Старые планы и ML-отчёты
сохраняются как история экспериментов, а не как параллельные списки обязательств.

Основание: [аудит кода, интерфейса и тестов](docs/release-audit-2026-09-08.md).
Выбран и внедрён **B — графитовый**. [Отчёт об интерфейсе и проверках](docs/design/graphite-implementation.md).
Исходные референсы: [A](docs/design/reference-a.html), [B](docs/design/reference-b.html).

## Где мы сейчас

**Работающий исследовательский MVP; следующий этап — стабилизация и выпуск.**
Это не начало проекта, но ещё не подтверждённо надёжный релиз. Наличие функции,
зелёные unit-тесты и качество ответа на реальном документе — разные вещи.

| Часть | Состояние | Что не даёт считать завершённой |
|---|---|---|
| FastAPI, PostgreSQL/pgvector, Docker, миграции, конфигурация | Реализовано | Нужен повторяемый запуск и интеграционные проверки релиза |
| PDF: загрузка, хранение, страницы, чанки, native/OCR RU+EN | Реализовано частично | Восстановление обработки после сбоя; геометрия OCR-цитат |
| Гибридный поиск, ответы с цитатами | Реализовано | Слабая точность финальных ответов; совпадение цитаты не доказывает вывод |
| Условия и риск-чеклист | Базовая версия | Четыре крупные категории, смешение типов сроков; грубые правила риска |
| React-интерфейс, RU/EN, просмотр PDF | Внедрён стиль B, исправлены выбор PDF и статусы | Нужны полный языковой аудит, OCR-геометрия и live API E2E |
| Обучение reranker, синтетические данные, real holdout | Есть эксперимент и отчёты | Кандидат не допущен в API по умолчанию; метрики требуют уточнения |
| Тесты, CI, документация | Основа есть | Браузерный mock-тест не проверяет настоящий PDF/API; roadmap был разрознен |
| Универсальный анализ | Не завершено | Нужен узкий fallback, а не обещание понимать любые PDF |

React заменяет первоначально запланированный Streamlit. Второй интерфейс не делаем.
Проценты готовности не назначаем: ниже перечислены проверяемые условия завершения.

## Граница релиза: что именно заканчиваем

Один пользователь, один документ за раз. Локальное развёртывание через Docker Compose.
Текстовые PDF на русском/английском и читаемые печатные сканы в заданных лимитах.
Основные действия: загрузить → получить условия → задать вопрос → проверить источник
на странице → сохранить результат. Неуверенность и отсутствие ответа явно показаны.

Для портфолио — публичное **read-only демо на синтетических документах** и полноценный
локальный режим. Публичная анонимная загрузка реальных документов не входит в v1.0:
для неё нужны отдельные ограничения доступа, хранения, нагрузки и удаления данных.

Бесплатный базовый режим сохраняем. Платный API необязателен; автоматических обращений
к нему при тестировании не делаем. Уже обученный reranker — кандидат, а не обязательный
компонент релиза. Не переобучаем модель с нуля ради галочки.

## Четыре следующих рабочих запроса

Это четыре законченных пакета работ, а не обещание уложить неизвестные проблемы
в фиксированное количество сообщений. При провале проверки сужаем заявленную поддержку
и фиксируем ограничение; не снижаем пороги задним числом и не называем проблему решённой.

### 1. Правильный документ, правильный ответ, честное измерение

Промежуточная реализация: [проверка ответов и evaluator v2](docs/answer-grounding-quality.md).
Добавлены восстановление полного предложения, проверка чисел/темы, совместные
метрики страницы и фрагмента, строгая валидация gate и регрессионные тесты.
Пакет **не закрыт**: нужны независимая разметка ответов, новый live baseline,
сложные таблицы/конфликты дат и полная фиксация версий пайплайна.

Дополнительно готов [расчёт OCR CER/WER](evals/real/ocr-evaluation.md) для
проверенных текстовых фрагментов; пропуски считаются ошибками. Это инструмент
измерения, не новый результат на реальных сканах. Старый holdout явно помечен
регрессионным. Независимая ручная проверка нового набора ещё не выполнена.

25 сентября выполнен [live regression QA](docs/live-quality-2026-09-25.md)
на сохранённом извлечённом тексте: span Hit@5 84,21%, совместная проверка
цитаты 31,58%, ошибочные отказы 52,63%. Gate не пройден. Свежий OCR/ingestion,
независимый answer gold и end-to-end candidate comparison всё ещё нужны.

- [x] Привязать локальный PDF/object URL к `document_id`; сбрасывать выбранную цитату
  и состояние вопроса при смене документа. Переход A → B, refresh и прямая ссылка
  должны показывать именно B.
- [x] Отделить готовность извлечения текста от готовности анализа. Ошибка анализа
  не блокирует просмотр PDF и независимый вопрос. Не ждать обновления списка,
  чтобы открыть уже успешно загруженный документ.
- [ ] Различать подачу заявки, поставку, выполнение работ и относительный период.
  Возвращать конкретное значение + короткое пояснение + подтверждающую цитату.
  Не превращать «60 дней с даты контракта» в выдуманную календарную дату.
- [ ] Добавить проверки соответствия чисел, дат, валют и отрицаний в ответе источнику;
  явно отказываться от неподтверждённого ответа. Это дополнительные проверки,
  не обещание автоматического доказательства любого естественно-языкового вывода.
- [ ] Исправить evaluator: считать попадание в нужный фрагмент, не только страницу;
  требовать страницу и достаточную цитату у одного evidence; учитывать пустой retrieval,
  ошибки, лишние утверждения и ошибочные отказы в знаменателях.
- [ ] Типизировать отчёты/gate, отклонять NaN/Infinity/неполные метрики. Записывать
  версии данных, модели, кода, настроек и размеры выборок. Старые результаты не менять.
- [ ] Новый regression-набор: разные даты, повторяющиеся суммы, таблицы, отсутствие ответа,
  смена документов, подмена числа при формально существующей цитате.

**Готово, когда:** все новые регрессии проходят, A/B не путаются, ответ не заявляет
неподтверждённую дату/сумму в этих сценариях, неполный отчёт не может разрешить модель.
Новый baseline измерен отдельно от исторического. Reranker остаётся выключенным.

### 2. Выбранный интерфейс и точное место ответа в PDF

- [x] Внедрить выбранный A или B, не две дизайн-системы сразу. Главная: компактная
  загрузка, список документов, понятные статусы. Декоративный атлас убрать из основного
  рабочего сценария; условия и ответы видны раньше оформления.
- [ ] Основной текст 15–16 px, значения 24–30 px, ясная иерархия, RU по умолчанию,
  EN без остаточных русских ошибок/подписей. Цитаты остаются на языке оригинала.
- [ ] Исправить PDF sizing при асинхронной загрузке и resize; независимое открытие
  оригинала без предварительного выбора цитаты, ошибки загрузки и повтор.
- [ ] Для native PDF сопоставлять цитату со страницей и точным диапазоном text layer.
  Не выделять похожие слова на другой странице; неоднозначность показывать явно.
- [ ] Для OCR сохранять координаты слов и параметры поворота/масштаба, возвращать
  нормализованные bounding boxes и накладывать их на PDF. Не обещать подсветку скана
  на основе одного plain text. Если локализовать не удалось — страница + цитата
  и явное «точное место не определено», без ложного выделения.
- [ ] Клавиатурная навигация, Escape, focus trap/return, неактивные скрытые панели;
  390/768/1440 px, масштаб 200%, reduced motion. Результаты и PDF не требуют
  горизонтального скролла всей страницы.
- [ ] Настоящий валидный PDF в browser-тестах: виден canvas, правильная страница,
  выделение нужного фрагмента; native, OCR и повёрнутый пример проверяются отдельно.

**Готово, когда:** выбранный стиль согласован, основные сценарии доступны на ноутбуке
и телефоне; автоматические проверки и визуальная проверка подтверждают страницу
и место цитаты. Если OCR-локализация ещё не прошла проверку, её статус остаётся partial.

### 3. Закрытый функциональный сценарий + ограниченный универсальный PDF

- [ ] Контракт условий: сроки подачи/исполнения, бюджет и валюта/НДС, оплата,
  обеспечение заявки/исполнения, штрафы, гарантия, требования. Для поля допустимы
  `found`, `not_found`, `ambiguous`; отсутствие не маскируется нулём.
- [ ] Риск = конкретное условие + объяснение + источник. Само наличие штрафа
  не равно высокому риску. Отсутствие найденного условия — вопрос на проверку,
  а не доказательство отсутствия его в документе или юридического нарушения.
- [ ] Сохранение результата анализа с версией; история вопросов хотя бы в рамках
  документа/сессии; один простой экспорт Markdown или JSON с цитатами и ограничениями.
- [ ] Повтор неудачной обработки, удаление документа и связанных данных, восстановление
  зависшей обработки после рестарта. Использовать существующую БД, без отдельного
  брокера задач, если нет доказанной необходимости. Тесты очистки и идемпотентности.
- [ ] Последнее функциональное расширение: профиль документа `tender / general / unknown`.
  Для общего PDF — краткое содержание и Q&A по источникам; для неизвестного профиля
  разрешить ручной выбор и не показывать выдуманные тендерные бюджет/штрафы.
  Это универсальность сценария, а не экспертный анализ любой отрасли.
- [ ] Тесты: поставка, работы, услуги и один нетендерный документ; неподдерживаемый,
  повреждённый, зашифрованный и слишком большой PDF имеют понятный исход.

**Готово, когда:** пользователь завершает цикл от загрузки до экспорта, возвращается
к результату, может повторить сбой/удалить файл; general PDF не выдаётся за тендер.

### 4. Независимая проверка, отчёт для ML-портфолио и выпуск

- [ ] После фиксации evaluator/порогов подготовить небольшой новый lockbox:
  минимум 6 независимых публичных исходных документов, минимум по 2 RU и EN,
  всего минимум 36 вопросов, из них минимум 8 без ответа. Это малая выпускная
  проверка, не статистическое доказательство универсального качества.
  Производные сканы одного PDF не считать независимыми документами.
- [ ] Выбирать источники после просмотра на персональные данные и условия использования.
  Сохранять URL, hash, дату, происхождение и журнал privacy review. Разметка содержит
  вопрос, допустимый ответ, страницу, точную цитату/ячейку и причины отказа.
  Отдельный человек должен подтвердить спорные gold-примеры; AI-разметку не называть
  независимой ручной проверкой. Если такой проверки нет — честно отметить ограничение.
- [ ] Таблицы, колонтитулы, поворот и шум — отдельный stress-набор; для OCR нужен
  вручную проверенный текст, CER/WER и точность локализации, не только «OCR завершился».
- [ ] Сравнить baseline и candidate на одинаковых входах по всей цепочке до ответа:
  retrieval, корректность факта, полнота/точность цитат, answerability, latency p50/p95,
  RAM. Отдельно cold/warm, native/OCR, RU/EN; указать железо и число наблюдений.
- [ ] Разработать и зафиксировать gate v2 до просмотра нового lockbox. Начальные
  требования: joint answer+page+quote accuracy ≥ 0.80 на answerable, корректный отказ
  ≥ 0.85 на unanswerable, отдельно измерять ложные отказы. Warm QA p95 ≤ 5 s на
  зафиксированном железе; ingest/OCR измерять отдельно. Малые группы публиковать
  как n/N, не скрывать средним. Эти числа — план, не достигнутые результаты.
- [ ] Для включения reranker: MRR +0.02 или больше, без ухудшения Hit@5,
  joint accuracy и отказов относительно baseline; обе цепочки проходят gate.
  Решение связано с hash модели/config/data; при несовпадении baseline fallback.
  Неуспех promotion не блокирует портфолио-релиз baseline, если он сам проходит gate.
- [ ] Если новый lockbox использован для подбора исправлений, он становится regression,
  а не остаётся независимым holdout. Не повторять настройку «до красивой метрики».
- [ ] ML-страница строится из версионированного безопасного JSON: baseline/candidate,
  разница, объём выборки, дата, статус gate. Обучение и тестирование разделены,
  синтетические и реальные результаты не смешиваются, нет выдуманных графиков.
- [ ] Docker с нуля, миграции, реальные API+Postgres+browser smoke без подмены API;
  lint/format/types/unit/E2E/negative tests, Windows-команды. Отдельно дешёвый CI
  и тяжёлые локальные OCR/ML проверки с сохранённым отчётом.
- [ ] README: короткое демо, скриншоты, архитектура, воспроизводимый эксперимент,
  model/data cards, измеренные ограничения, инструкция запуска, статус публичного
  read-only демо. Веса, ключи и непроверенные реальные PDF вне Git.
- [ ] Разобрать цепочку PR, интегрировать только проверенные изменения; не закрывать
  старые ветки без проверки уникальных коммитов. Итоговый review → merge по принятому
  порядку → версия v1.0. Не объявлять текущую экспериментальную ветку уже выпущенной.

**Готово, когда:** выпуск воспроизводится, все обязательные проверки имеют результат,
критические ошибки закрыты, выбранный режим проходит gate, демо показывает реальные
возможности, а неподдерживаемые сценарии явно перечислены. При провале — release candidate,
а не «всё готово».

## Что сознательно не делаем до v1.0

Собственную LLM с нуля; бесконечный выбор моделей; две отдельные frontend-реализации;
агентную платформу; мультитенантность/платежи; сравнение пакетов документов; рукопись;
юридические рекомендации; поддержку всех языков и форматов; сложные лендинговые
анимации; Kubernetes/микросервисы. Это backlog после релиза, не долг текущего MVP.

## Как продолжать

Следующий запрос: «Выполняй оставшуюся часть пакета 1 из ROADMAP.md: качество ответов и evaluator».
Выбор дизайна закрыт; внедрение B выполнено раньше остальной части пакета 2 по запросу
пользователя. Пакеты 1 и 2 целиком пока не завершены.
Перед каждым пакетом — коротко что меняем и зачем, затем код и тесты, затем результат
по критериям выше. Один источник правды — этот файл; отмечать checkbox только после
проверки, а не после появления первого прототипа.
