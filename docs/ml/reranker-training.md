# Обучение TenderLens-Reranker

Этот документ объясняет ML-часть проекта простыми словами и фиксирует результаты без
заявлений о юридической или production-точности.

## Зачем нужен reranker

Hybrid retrieval быстро находит несколько потенциально подходящих фрагментов PDF. Среди них
часто есть тексты с похожими словами, но другим смыслом: например, «обеспечение заявки - 2%»
и «обеспечение исполнения контракта - 5%».

Reranker получает пару `вопрос + фрагмент` и оценивает ее релевантность. В отличие от
embeddings, cross-encoder читает вопрос и фрагмент совместно, поэтому лучше различает такие
тонкие случаи.

```text
PDF chunks -> hybrid retrieval candidates -> TenderLens-Reranker -> top fragments -> answer
```

Мы не обучаем большую языковую модель с нуля. Исходная multilingual-модель
[`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)
уже понимает русский и английский тексты. Fine-tuning адаптирует ее к тендерным формулировкам.

## Датасет v2

Исходные сценарии лежат в
[`evals/synthetic_tender_corpus_v2.json`](../../evals/synthetic_tender_corpus_v2.json), а
детерминированный генератор создает
[`evals/reranker_dataset_v2.jsonl`](../../evals/reranker_dataset_v2.jsonl).

| Split | Документов | Вопросов | Пар вопрос-фрагмент | Назначение |
| --- | ---: | ---: | ---: | --- |
| train | 16 | 384 | 1 536 | обновление весов |
| validation | 4 | 96 | 384 | выбор лучшей эпохи |
| test | 4 | 96 | 384 | финальная проверка |
| всего | 24 | 576 | 2 304 | RU: 384, EN: 192 |

Для каждого из восьми типов условий создано по три перефразированных вопроса. У каждого
вопроса есть один правильный фрагмент и три hard negatives из того же документа. Например,
для обеспечения заявки отрицательными примерами служат обеспечение исполнения, штраф и
бюджет. Это сложнее и полезнее случайных нерелевантных абзацев.

Разбиение выполняется по `document_id`: один документ не может попасть в несколько split.
Валидатор отдельно проверяет утечки, дубликаты, обязательные поля и соответствие числа
отрицательных категорий. Воспроизводимость проверяется командой:

```powershell
uv run python scripts/build_reranker_dataset.py --check
```

## PDF evaluation pack

Двенадцать сценариев также собраны в настоящие трехстраничные PDF в
[`output/pdf/tenderlens-eval-v2`](../../output/pdf/tenderlens-eval-v2). Каждый файл явно
помечен как синтетический и не содержит персональных данных. Manifest хранит 96 вопросов,
ожидаемые значения и страницы.

```powershell
uv run python scripts/generate_synthetic_pdfs.py
uv run python scripts/verify_pdf_pack.py
uv run python scripts/smoke_pdf_pack.py
```

`verify_pdf_pack.py` проверяет 36 страниц и наличие всех 96 эталонных фрагментов в извлеченном
тексте. `smoke_pdf_pack.py` загружает те же PDF через работающий FastAPI и использует настоящие
retrieval, question answering, citations и file endpoint.

Первый прогон обнаружил ошибки бесплатного extractive-режима: accuracy точного значения была
0.822917, а страницы цитаты - 0.958333. После category-aware выбора предложений результат на
том же regression-наборе стал 1.0 для страницы и значения. Это проверка регрессий, а не
доказательство качества на произвольных реальных документах.

## Метрики reranker

- `Hit@1` - правильный фрагмент стоит первым.
- `Hit@3` - правильный фрагмент входит в первую тройку.
- `MRR` - насколько близко к началу находится правильный результат.
- `nDCG@3` - качество позиции правильного результата в top-3.
- `mean_positive_rank` - средняя позиция правильного фрагмента; меньше лучше.

Результаты на неизменяемых validation и test документах:

| Модель | Validation Hit@1 | Test Hit@1 | Test MRR | Test Hit@3 |
| --- | ---: | ---: | ---: | ---: |
| совпадение слов | 0.572917 | 0.593750 | 0.719618 | 0.697917 |
| исходный multilingual cross-encoder | 0.875000 | 0.875000 | 0.926215 | 0.968750 |
| TenderLens-Reranker v1 | 0.989583 | 0.989583 | 0.993056 | 1.000000 |

Дообученная модель ошиблась в одном из 96 test-вопросов: для английского вопроса о сроке
исполнения выше правильного фрагмента поставила гарантийный срок. Ошибка сохранена в
[`evals/reranker_tuned_v2.json`](../../evals/reranker_tuned_v2.json), а итог обучения - в
[`evals/reranker_experiment_v1.json`](../../evals/reranker_experiment_v1.json).

## Воспроизведение обучения

ML-зависимости отделены от обычного backend и production Docker image:

```powershell
uv sync --dev --extra ml
uv run --extra ml python scripts/train_reranker.py `
  --base-model cross-encoder/mmarco-mMiniLMv2-L12-H384-v1 `
  --output-dir models/tenderlens-reranker-v1 `
  --epochs 2 `
  --batch-size 16 `
  --learning-rate 1e-5 `
  --max-length 192
```

Эксперимент выполнялся на CPU с seed 42 и занял около двух минут без платного API. Pipeline
сохраняет checkpoint с минимальным validation loss, а не последнюю эпоху. Веса находятся в
игнорируемой папке `models/` и не коммитятся в Git.

## Решение о внедрении

Статус модели - `research_candidate`, а не production. Улучшение на синтетическом holdout
значительное, но шаблоны train, validation и test созданы одним генератором. Поэтому модель
может хорошо выучить структуру корпуса и хуже работать на документах других организаций.

Перед включением reranker по умолчанию нужны:

1. независимо размеченный набор публичных или лицензированных реальных документов;
2. OCR-примеры, таблицы, колонтитулы и длинные юридические формулировки;
3. вопросы без ответа и проверка корректного отказа;
4. hard negatives из реального top-20 текущего hybrid retrieval;
5. измерение latency и памяти внутри Docker;
6. публикация versioned model artifact с model card, а не весов в Git.

Исторический seed v1 и неудачный эксперимент v0 сохранены в репозитории. Они показывают,
почему маленький test из восьми вопросов не позволял честно подтвердить улучшение.
