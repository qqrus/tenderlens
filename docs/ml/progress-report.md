# Отчёт о прогрессе ML-части TenderLens

Дата среза: 22 августа 2026 года. Эксперимент: `TenderLens-Reranker v1`.

## Короткий итог

Мы не обучали большую языковую модель с нуля. Это было бы дорого и не дало бы полезного
результата на небольшом датасете. Вместо этого взяли готовый multilingual cross-encoder и
дообучили его различать близкие по смыслу тендерные условия: бюджет, обеспечение заявки,
обеспечение исполнения, штраф, срок, оплату, гарантию и поставку.

На синтетическом test-наборе правильный фрагмент стал первым в выдаче в 98,96% случаев вместо
87,50% у исходной модели. Это прирост 11,46 процентного пункта. Одна ошибка из 96 вопросов
сохранилась: английский вопрос о сроке исполнения был спутан с гарантийным сроком.

## Результаты

| Метод | Test Hit@1 | Test MRR | Test Hit@3 |
| --- | ---: | ---: | ---: |
| Совпадение слов | 59,38% | 71,96% | 69,79% |
| Исходный multilingual cross-encoder | 87,50% | 92,62% | 96,88% |
| TenderLens-Reranker v1 | 98,96% | 99,31% | 100,00% |

`Hit@1` отвечает на самый понятный вопрос: как часто правильный фрагмент оказался первым.
`MRR` учитывает его среднюю позицию, а `Hit@3` — попал ли он хотя бы в первую тройку.

Вопросы разделены по документам: один и тот же документ не попадает одновременно в train и
test. В наборе 384 русских и 192 английских вопроса. У каждого положительного фрагмента есть
три сложных отрицательных примера из того же документа.

## Что уже улучшено в продукте

- Hybrid retrieval ищет кандидатов по смыслу и по словам.
- Reranker обучен на тендерных формулировках без платного LLM API.
- Ответы привязаны к странице, точной цитате и символьным координатам.
- Для условий API отдельно возвращает проверяемое значение: дату, сумму или процент. Полная
  фраза из PDF остаётся рядом как контекст.
- Создан воспроизводимый evaluation pipeline и реалистичный синтетический PDF-набор.

## Ограничения

Статус модели — `research_candidate`, не production. Train, validation и test созданы одним
генератором, поэтому высокая метрика не доказывает такое же качество на документах других
организаций. Пока не измерено качество на независимо размеченном реальном наборе, нельзя
обещать 98,96% на произвольных тендерах.

## Следующий этап

1. Собрать небольшой privacy-reviewed holdout из публичных реальных документов.
2. Вручную разметить вопросы, ответы, страницы и вопросы без ответа.
3. Добавить OCR-примеры, таблицы, колонтитулы и сканы низкого качества.
4. Сравнить baseline и reranker на этом наборе, отдельно измерить citation accuracy и latency.
5. Только после прохождения quality gate подключать reranker в API по умолчанию.

Подробности воспроизведения обучения находятся в
[`docs/ml/reranker-training.md`](reranker-training.md).
