# Табличная ячейка → проверяемый источник

19 октября 2026. Экспериментальная вертикальная связка поверх geometry snapshot.

## Что работает

- POST `/api/v1/documents/{id}/table-answer`: SHA-256 источника, индекс таблицы,
  точные подписи строки и столбца. В ответе document ID, SHA-256, размер страницы
  и три ячейки с текстом/прямоугольниками. Не создаём фиктивные chunk ID/offsets.
- Только готовый документ и ready snapshot. Пустая, отсутствующая или неоднозначная
  ячейка → отказ. Таблица выбирается явно; одинаковые подписи внутри неё не угадываются.
- «Вопросы → Ответ из таблицы · эксперимент»: выбор, крупный текст результата,
  переход к источнику. Строка жёлтая, столбец фиолетовый, значение синее.
- Браузер вычисляет SHA-256 фактически открытого Blob (включая локальную загрузку).
  Несовпадение скрывает геометрическую подсветку. Чужой document ID не открывается.
- Прямоугольники в процентах масштабируются вместе со страницей; на другой странице
  не показываются. Для поворота, ненулевого начала crop box или несовпадения размеров
  подсветка отключена с пояснением. При неверном прямоугольнике вся тройка скрыта.

## Как проверить

Нужен **новый** native PDF с простой таблицей, включённый `TABLE_GEOMETRY_ENABLED=true`
при ingestion и не более `TABLE_GEOMETRY_MAX_PAGES` страниц. Дедупликация не выполняет
backfill старого документа. Если snapshot отсутствует, интерфейс прямо сообщает это.
Оригиналы и существующие строки БД автоматически не меняем.

Локальные проверки:

```powershell
uv run --extra tables pytest -q
cd frontend
pnpm typecheck
pnpm lint
pnpm test
$env:E2E_PORT = '5186'
pnpm test:e2e
pnpm build
```

Браузерные тесты используют реальный отслеживаемый синтетический PDF и координаты,
снова извлечённые pdfplumber, но HTTP ответы подменены. Для них нужен `uv`/Python
в корне репозитория. Это не независимый holdout и не live API E2E. Проверены три
рамки, положение с допуском 2 CSS px, мобильный resize, смена страниц, неверный hash.
Исходная страница дополнительно просмотрена через Poppler, screenshots — вручную.

Результаты: backend 206 passed, покрытие 87,65%; frontend 18 unit и 7 browser tests
passed. Ruff, mypy, TypeScript, ESLint и production build прошли.

## Ограничения и следующие шаги

Это чтение выбранной ячейки, **не новая обученная модель** и не интерпретация
содержимого. Первую строку считаем заголовком, первый столбец — подписью строки.
Декоративная рамка тоже может быть обнаружена как таблица. Единицы, примечания,
многоуровневые шапки, merged cells и переходы между страницами автоматически
не разрешаются. Обычные `/questions` остаются прежними; качество ответов на
регрессионном наборе заново не измерялось, gate по-прежнему закрыт.

Дальше: ограниченный автоматический выбор строки/столбца из вопроса с отказами;
оценка полного ответа и тройки evidence на размеченных примерах; безопасная явная
переобработка старых документов; отдельно OCR-координаты и преобразования страниц.
Не включать reranker по умолчанию без независимой проверки gate.
